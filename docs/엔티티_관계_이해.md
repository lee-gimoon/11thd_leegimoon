# 엔티티 관계 이해

이 문서는 프로젝트 협업 서비스에서 `User`, `Project`, `ProjectMember`, `Task`가 어떤 관계를 가지는지 설명합니다.

## 1. 전체 관계

```text
User 1 ───< ProjectMember >─── 1 Project
                                  |
                                  └──< Task

Task ─── 담당자 ───> User (선택 사항)
```

`ProjectMember`는 사용자와 프로젝트의 소속 관계를 나타내는 중간 엔티티입니다. 따라서 사용자는 여러 프로젝트에 참여할 수 있고, 프로젝트에는 여러 사용자가 참여할 수 있습니다.

```text
User 1 ───< ProjectMember >─── 1 Project
```

이는 `User`와 `Project` 사이의 다대다 관계를 `ProjectMember`로 풀어낸 형태입니다. `ProjectMember`에는 단순한 연결 정보뿐 아니라 해당 프로젝트에서의 역할도 저장합니다.

```text
OWNER  : 프로젝트 소유자
ADMIN  : 프로젝트 관리자
MEMBER : 일반 참여자
```

## 2. Project와 Task의 관계

프로젝트 하나에는 여러 작업이 있고, 작업 하나는 반드시 하나의 프로젝트에 속합니다.

```text
Project 1 ───< Task
```

그래서 `Task` 엔티티에는 다음 관계가 있습니다.

```java
@ManyToOne(fetch = FetchType.LAZY, optional = false)
@JoinColumn(name = "project_id", nullable = false)
private Project project;
```

`tasks` 테이블의 `project_id` 외래 키가 작업이 속한 프로젝트를 가리킵니다. `optional = false`와 `nullable = false`는 프로젝트 없이 작업을 만들 수 없음을 JPA와 데이터베이스 수준에서 각각 나타냅니다.

## 3. Task와 담당자의 관계

작업에는 담당자가 있을 수도, 없을 수도 있습니다.

```java
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "assignee_id")
private User assignee;
```

여기서 `Task`는 `ProjectMember`를 직접 참조하지 않고 `User`를 담당자로 참조합니다.

```text
Task ─── 담당자 ───> User
```

다만 담당자로 지정할 수 있는 사용자는 아무 사용자나 될 수 없습니다. 서비스 계층에서 해당 사용자가 작업의 프로젝트에 `ProjectMember`로 가입되어 있는지 확인한 뒤에만 담당자로 저장합니다.

```text
Task가 A 프로젝트에 속함
        ↓
담당자 후보 User가 A 프로젝트의 ProjectMember인지 확인
        ↓
가입되어 있으면 Task.assignee에 User를 저장
```

즉, 각 엔티티의 역할은 다음과 같이 구분됩니다.

| 엔티티 | 의미 |
| --- | --- |
| `User` | 서비스 전체에서 사용하는 사용자 |
| `Project` | 협업이 이루어지는 작업 공간 |
| `ProjectMember` | 사용자의 프로젝트 소속 여부와 프로젝트 내 역할 |
| `Task` | 특정 프로젝트 안에서 관리하는 작업 |
| `Task.assignee` | 그 작업을 담당하는 사용자. 없을 수 있음 |

## 4. 예시

민수는 A 프로젝트와 B 프로젝트에 참여할 수 있습니다.

```text
User: 민수

ProjectMember:
- 민수 → A 프로젝트 → OWNER
- 민수 → B 프로젝트 → MEMBER

Task:
- A 프로젝트 → "로그인 구현" → 담당자 민수
- B 프로젝트 → "테스트 작성" → 담당자 민수
```

민수는 두 프로젝트에 모두 멤버로 등록되어 있으므로 두 작업의 담당자가 될 수 있습니다. 반대로 A 프로젝트의 멤버가 아닌 사용자는 A 프로젝트 작업의 담당자로 지정할 수 없습니다.

## 5. 한 줄 정리

`ProjectMember`는 **사용자가 프로젝트에 참여할 자격과 역할**을 나타내고, `Task`는 **프로젝트 안의 작업과 담당 사용자**를 나타냅니다.
